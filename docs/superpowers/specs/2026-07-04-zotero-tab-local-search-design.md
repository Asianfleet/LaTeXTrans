# Zotero Tab 本地搜索与附件导入设计

## 背景

当前 Textual TUI 的项目详情页已经有 Zotero tab，用于把当前项目生成的 PDF 附加到用户手动指定的 Zotero 条目。本次只调整 Zotero tab 的交互规格：搜索使用 Zotero 本地 API，附件导入继续使用 Zotero Web API，并在 UI 配置与设置页中新增 Zotero 配置段。

## 目标

- Zotero tab 分为上下两部分：上方操作栏，下方数据表。
- 上方操作栏固定为 `[select][搜索框][搜索按钮][自动匹配按钮][一条竖向 Rule][导入按钮]`。
- `select` 列出所有可选库，用于选择搜索范围。
- 搜索框输入内容后，点击搜索按钮或按回车触发搜索。
- 自动匹配按钮查找“存档id”字段含有本次任务 arXiv ID 的条目。
- 如果本次任务不是 arXiv ID，则竖向 Rule 和导入按钮不显示。
- 数据表固定列为 `选中`、`标题`、`所在库`、`所在分类`。
- 条目列表支持多选，选中列用 `[√]` 表示选中，用 `[]` 表示未选中，默认 `[]`。
- 点击导入时，对每个选中的条目执行附件导入。
- 搜索使用本地 API，导入使用 Web API。
- UI 配置文件新增 `[zotero]` 配置段，设置 tab 对应新增可编辑项。

## 非目标

- 不新增 Zotero 条目。
- 不直接导入 arXiv URL 生成 Zotero 条目。
- 不改变翻译任务创建、运行、输出目录或详情页其他 tab。
- 不把 Zotero 导入变成翻译任务的强依赖。
- 不改变数据表列顺序和列名。
- 不在本次规格中增加未提出的筛选、排序、分页、语义搜索或去重能力。

## UI 布局

Zotero tab 使用一个垂直容器承载两部分：

1. 上方操作栏。
2. 下方数据表。

上方操作栏使用水平布局，控件顺序必须是：

```text
[select][搜索框][搜索按钮][自动匹配按钮][一条竖向 Rule][导入按钮]
```

控件含义：

- `select`：列出所有可选 Zotero 库，当前值决定搜索范围。
- `搜索框`：输入普通搜索文本。
- `搜索按钮`：使用搜索框文本，在当前选中库内搜索。
- `自动匹配按钮`：搜索“存档id”字段含有本次任务 arXiv ID 的条目。
- `一条竖向 Rule`：仅作为自动匹配区域与导入按钮之间的视觉分隔。
- `导入按钮`：对数据表中所有选中条目执行附件导入。

显示规则：

- 当本次任务是 arXiv ID 时，显示完整操作栏。
- 当本次任务不是 arXiv ID 时，不显示竖向 Rule 和导入按钮。
- 其他控件是否可用不受任务类型影响。

下方数据表列固定为：

1. `选中`
2. `标题`
3. `所在库`
4. `所在分类`

表格行代表 Zotero 条目。每一行内部必须保留导入所需的条目 key、库 id、库类型和分类 key 或分类名称，但这些内部字段不显示为独立列。

## 交互逻辑

### 库选择

打开 Zotero tab 时，应用从 Zotero 本地 API 获取所有可选库，并填充到 `select`。每个选项至少应携带：

- 展示名称。
- `library_id`。
- `library_type`。

普通搜索和自动匹配都必须使用当前 `select` 选中的库作为搜索范围。

### 普通搜索

用户在搜索框输入内容后：

- 点击搜索按钮触发搜索。
- 在搜索框按回车触发同一搜索。

搜索使用 Zotero 本地 API，从当前选中库查询条目。搜索结果替换当前数据表内容。每个新增结果行的 `选中` 列默认为 `[]`。

### 自动匹配

自动匹配按钮的规则是：

```text
找到所有“存档id”字段含有本次任务 arXiv ID 的条目。
```

自动匹配也使用 Zotero 本地 API，并限定在当前选中库内。自动匹配结果替换当前数据表内容。每个新增结果行的 `选中` 列默认为 `[]`。

如果当前项目或当前任务无法提供 arXiv ID，自动匹配不应执行搜索，并应给出状态提示。

### 多选

数据表支持多选。点击条目行时切换该行选中状态：

- 未选中时，`选中` 列显示 `[]`。
- 选中后，`选中` 列显示 `[√]`。
- 再次点击后，恢复为 `[]`。

表格刷新搜索结果时，默认清空既有选择状态。

### 附件导入

点击导入按钮时：

1. 读取当前数据表中所有 `选中` 列为 `[√]` 的条目。
2. 对每个选中条目执行一次附件导入。
3. 附件导入使用 Zotero Web API。
4. 每次导入使用该行内部保存的 `library_id`、`library_type` 和条目 key。
5. 导入的附件是当前项目生成的 PDF。

如果没有选中条目，导入按钮应给出状态提示，不执行 Web API 请求。

如果当前项目没有可导入 PDF，导入按钮应给出状态提示，不执行 Web API 请求。

## API 边界

搜索和库列表使用本地 API：

```toml
[zotero]
local_api_base = "http://127.0.0.1:23119/api"
```

导入使用 Web API，API key 从配置指定的环境变量名读取：

```toml
[zotero]
web_api_key_env = "ZOTERO_API_KEY"
```

实现不得把 Web API key 写入 UI 配置文件。配置文件只保存环境变量名。

## UI 配置

UI 配置文件新增：

```toml
[zotero]
local_api_base = "http://127.0.0.1:23119/api"
web_api_key_env = "ZOTERO_API_KEY"
```

设置 tab 需要相应新增 Zotero 配置项：

- `local_api_base`：字符串输入项。
- `web_api_key_env`：字符串输入项。

设置 tab 保存配置时，应保留 `[zotero]` 段，并把这两个字段写回 UI 配置文件。

## 状态与错误处理

Zotero tab 应提供状态反馈，用于显示：

- 本地 API 不可用。
- 没有可选库。
- 未选择库。
- 搜索框为空时无法普通搜索。
- 自动匹配缺少 arXiv ID。
- 搜索无结果。
- 未选择任何条目。
- 当前项目没有 PDF。
- Web API key 环境变量未设置。
- 单个条目导入成功或失败。

批量导入时，单个条目失败不应阻止其他选中条目继续导入。最终状态应能表达成功数量和失败数量。

## 测试要求

新增或更新 `unittest` 覆盖以下行为：

- Zotero tab 上方操作栏控件顺序为 `select`、搜索框、搜索按钮、自动匹配按钮、竖向 Rule、导入按钮。
- 非 arXiv 任务不显示竖向 Rule 和导入按钮。
- 数据表列固定为 `选中`、`标题`、`所在库`、`所在分类`。
- 搜索按钮和搜索框回车触发本地 API 搜索，并使用当前选中库。
- 自动匹配按“存档id”字段包含当前 arXiv ID 的规则调用本地 API。
- 搜索结果默认 `选中` 列为 `[]`。
- 点击行能在 `[]` 和 `[√]` 之间切换。
- 导入按钮只对 `[√]` 行执行 Web API 附件导入。
- UI 配置加载、设置页展示和保存都包含 `[zotero]` 的两个字段。

## 兼容性

- 现有 CLI 行为不变。
- 现有翻译任务运行行为不变。
- 现有 Zotero 附件导入的 Web API 边界保留。
- 本次修订替换旧 Zotero tab 中手动输入库 id、库类型和 item key 的交互。
