# Textual 终端界面设计

## 背景

LaTeXTransPlus 目前以 CLI 为主，已经具备：

- `runtime.prepare_projects()` 将 arXiv、本地项目、本地压缩包、远程压缩包统一整理为可处理的项目目录。
- `runtime.run_projects()` 通过 `event_callback` 输出项目级结构化事件。
- `src/events.py` 已提供 JSON Lines 事件流能力。
- 各项目的普通日志与输出文件都落在 `outputs/<target_language>_<project_name>/`。

本次要新增一个基于 Textual 的终端 UI，作为交互入口。该 UI 不替代 CLI，而是复用现有运行时和输出目录结构，为批量处理、结果查看、Zotero 导入和配置编辑提供一个统一工作台。

## 目标

- 提供一个 Textual TUI 作为独立入口。
- 左侧固定栏常驻，右侧内容区可切换不同页面。
- 支持单次任务选择一种输入类型，并批量输入多个条目。
- 支持 arXiv ID / URL、本地项目/压缩包、远程压缩包三类输入。
- 支持显示任务进度，并消费现有运行时事件。
- 支持查看项目结果、翻译后的 tex 文件、术语表和错误记录。
- 支持打开文件资源管理器。
- 支持将翻译后的 PDF 作为附件导入 Zotero 现有条目。
- 支持独立的 UI 配置文件编辑。
- Footer 显示按键绑定。

## 非目标

本次不实现以下内容：

- 不改写现有 CLI 为纯 UI 专用流程。
- 不把 `--all-existing` 作为 UI 首版入口。
- 不在 TUI 中提供完整 tex 编辑器，只做查看。
- 不把 Zotero 导入做成翻译流程的强依赖。
- 不新增后台常驻服务、HTTP API 或 IPC 服务。
- 不支持多种输入类型混合提交到同一任务。

## 总体方案

采用“单一主 App + 左侧常驻栏 + 右侧内容切换”的结构。

Textual App 只负责布局、交互、状态分发和视图切换；翻译工作继续由现有 `runtime` 层完成，后台 worker 通过现有事件回调把状态推回 UI。右侧内容区不使用多 `Screen` 叠加主布局，而是使用统一的 `ContentSwitcher` 承载多个视图，这样左侧栏、Footer 和全局状态都能保持稳定。

UI 配置使用独立配置文件，不直接复用翻译配置文件作为写入目标。启动时如果存在 `config/default.toml`，将其复制为 UI 配置基底；否则基于 `config/template.toml` 生成 UI 配置。这样 UI 的默认布局、快捷键和外部集成设置可以单独演进。

## 组件清单

本次实现明确使用以下 Textual 组件：

- 布局：`App`、`Horizontal`、`Vertical`、`VerticalScroll`、`ContentSwitcher`、`TabbedContent`、`TabPane`
- 交互：`Button`、`Select`、`Input`、`TextArea`、`Switch`
- 列表与表格：`ListView`、`ListItem`、`DataTable`
- 状态与日志：`ProgressBar`、`RichLog`、`Static`
- 底栏：`Footer`

组件职责边界：

- `ContentSwitcher` 只负责右侧 5 个主页面切换。
- `TabbedContent` 只负责详情页内部的子视图切换。
- `ListView` / `ListItem` 只负责左侧项目/结果列表。
- `DataTable` 只负责任务管理页、术语表、错误记录等结构化展示。
- `TextArea` 只负责批量输入、只读 tex 预览和 UI 配置文本编辑。
- `RichLog` 只负责实时进度日志和事件摘要。
- `ProgressBar` 只负责任务进度可视化。

## 页面与布局

### 主布局

主窗口固定为左右布局加 Footer：

- 左侧：顶部按钮区、中部项目/结果列表、底部设置按钮。
- 右侧：内容切换区。
- 底部：Footer，显示按键绑定。

左侧按钮区包含：

- `新建任务`，使用 `Button`
- `任务管理`，使用 `Button`

左侧底部包含：

- `设置`，使用 `Button`

### 右侧页面

右侧切换 5 个页面：

1. 入口页
2. 任务进度页
3. 详情页
4. 任务管理页
5. 配置页

### 入口页

入口页是默认页，顶部显示标题 `LaTeXTransPlus`。标题下方提供输入区：

- 左侧使用 Textual `Select` 选择输入类型
- 右侧使用 Textual `TextArea` 输入多个条目

输入类型只允许单选，且任务提交前必须确定类型。支持的类型为：

- `arxiv`
- `local`
- `remote`

同一任务中多个条目可以换行或逗号分隔，但不能混入其他类型内容。

### 任务进度页

提交入口页后切换到任务进度页。该页显示：

- 当前任务名称
- 总项目数
- 当前处理项目
- 成功数
- 失败数
- 实时事件摘要
- 最近一条日志摘要

页面组件以 `ProgressBar`、`Static` 和 `RichLog` 为主。

进度页不重新展示输入内容，不允许修改已提交任务。

### 详情页

点击左侧项目/结果列表条目后切换到详情页。该页展示单个项目的详细结果，包括：

- 翻译后的 tex 文件预览，使用只读 `TextArea`
- 术语表，使用 `DataTable`
- 错误记录，使用 `DataTable`
- PDF 路径
- 日志路径
- 打开资源管理器
- 打开 PDF
- 导入 Zotero

详情页内部使用 `TabbedContent` + `TabPane` 切换 tex、术语表、错误记录和日志等子视图。

详情页只对当前选中的项目生效。

### 任务管理页

任务管理页用于查看每个条目的完整状态和详细信息。此页保持左侧列表存在，但列表项展示更简略；主区域展示每个任务的详细字段和操作入口。

主区域使用 `DataTable` 展示任务字段、状态和路径。

### 配置页

配置页编辑独立的 UI 配置文件。该文件不等同于翻译配置文件，但其初始化来源遵循：

- 若 `config/default.toml` 存在，则复制其内容作为 UI 配置初始值。
- 若 `config/default.toml` 不存在，则基于 `config/template.toml` 创建 UI 配置。

配置页采用表单式编辑，字段类型分别使用：

- `Input`：字符串和路径
- `Select`：枚举项
- `Switch`：布尔项
- `TextArea`：多行文本和完整 TOML 预览

配置页支持保存与重新载入。

## 状态模型

应用级状态拆分为三层：

- 全局状态：当前任务、当前选中项目、当前 Zotero 库、当前 UI 配置、当前右侧页面
- 列表状态：每个项目的输入类型、解析状态、翻译状态、输出路径、日志路径、PDF 路径、术语表路径、错误记录路径、Zotero 关联状态
- 页面状态：右侧页面的局部显示状态和聚焦项

所有页面共享同一份项目状态，避免页面切换后状态丢失。

## 输入与任务流

### 输入类型规则

任务创建时先选输入类型，再输入多个条目。

类型规则：

- `arxiv`：接受 arXiv ID 或 arXiv URL
- `local`：接受本地项目目录或本地压缩包路径
- `remote`：接受远程压缩包 URL

一次任务只允许一种类型，不允许混合。

### 任务流

1. 用户在入口页选择输入类型并输入多个条目。
2. UI 校验输入类型与格式。
3. UI 调用现有运行时准备项目。
4. 运行时按项目顺序执行翻译。
5. UI 通过事件回调更新进度页和列表状态。
6. 用户可在结果可用后切换到详情页查看 tex、术语表和错误记录。
7. 用户可选择某个 Zotero 条目，将当前项目生成的 PDF 作为附件导入。

### 进度更新

TUI 直接消费现有项目事件，而不是解析普通 stdout。第一版只依赖：

- `run_start`
- `project_start`
- `project_complete`
- `project_error`
- `run_complete`

## Zotero 集成

第一版只实现以下功能：

- 选择 Zotero 库
- 搜索已有条目
- 选中条目
- 将当前项目生成的翻译 PDF 作为附件导入该条目

Zotero 选择与搜索界面使用 `Input`、`ListView`、`ListItem`、`Button` 和 `Static`。

不实现：

- 新建 Zotero 条目
- 直接导入 arXiv URL 生成条目
- 自动匹配条目

若 Zotero 不可用或未配置，导入动作应失败但不影响翻译结果展示。

## 文件查看与外部动作

详情页支持以下动作：

- 在系统文件资源管理器中打开项目输出目录
- 打开翻译后的 PDF
- 打开译文 tex 文件，并优先以只读文本视图展示；实现上使用只读 `TextArea`
- 查看术语表和错误记录

查看 tex 文件采用只读预览，不提供编辑器能力。

## Textual 实现边界

Textual App 负责：

- 布局组合，右侧页面切换使用 `ContentSwitcher`
- 页面切换
- 表单输入，输入类型选择使用 `Select`，批量输入使用 `TextArea`
- 列表选择
- Footer 快捷键展示
- 后台 worker 启动与结果回传

运行时层继续负责：

- 项目准备
- 项目执行
- 结构化事件发出
- 输出目录与项目结果的生成

TUI 不直接实现翻译逻辑，也不替代现有 CLI 参数处理。

## 错误处理

- 输入类型未选时禁止提交任务。
- 多个条目中单个条目格式错误时，应在入口页给出明确错误，不启动任务。
- 某个项目翻译失败时，列表状态和进度页应显示失败，但不阻断其他项目。
- Zotero 导入失败时，只影响该次导入动作，不影响翻译任务本身。
- 配置文件不存在或不可写时，应明确提示并保留当前已加载配置。

## 测试计划

测试继续使用 `unittest`。

重点覆盖：

- 左右布局与右侧页面切换。
- 输入类型单选与批量输入校验。
- 入口页提交后自动切换到进度页。
- 列表条目点击后切换到详情页。
- 任务管理页展示简略列表和详细信息。
- UI 配置文件初始化规则。
- 翻译输出与 Zotero 导入动作的状态更新。

## 兼容性

- 现有 CLI 行为不变。
- 现有 `runtime.run_projects()` 事件契约保持兼容。
- 现有输出目录结构保持不变。
- UI 配置与翻译配置分离，不回写 `config/default.toml`。

## 决策总结

本次 Textual TUI 采用：

- 左右布局加 Footer
- 左侧常驻栏 + 右侧内容切换
- 单任务单输入类型
- 进度由现有运行时事件驱动
- 详情页承载 tex、术语表、错误记录和外部动作
- Zotero 只做 PDF 附件导入到已有条目
- UI 配置独立管理，优先复制 `config/default.toml`，否则基于 `config/template.toml`
